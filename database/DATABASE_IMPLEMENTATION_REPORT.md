# تقرير الإنجاز الهندسي لبناء وتصميم قاعدة بيانات «دلنّي» المتوافقة مع Supabase
## Dalani Platform Database Implementation & Engineering Report

---

## 1. ملخص تنفيذي (Executive Summary)

تم إنجاز وتصميم قاعدة بيانات علائقية سيادية ومتكاملة لمنصة **«دلنّي - المنصة العقارية اليمنية»** متوافقة بنسبة 100% مع بيئة **Supabase / PostgreSQL 15+**. 
تم استخلاص وهندسة هذا المخطط بالاعتماد الحصري والدقيق على الفحص الفعلي للكود المصدري للمشروع، متضمناً:
- ملفات تعريف النماذج والأنماط في `src/types/index.ts`.
- مخطط Drizzle ORM الحالي في `src/db/schema.ts`.
- منطق الأعمال ونقاط النهاية (API Endpoints) في `server.ts` و `src/server/db.ts`.
- البيانات الجغرافية والافتراضية للجمهورية اليمنية في `src/data/yemenData.ts`.
- الوثيقة المرجعية الاستراتيجية `PROJECT_ANALYSIS_AND_ROLES_GUIDE.md`.

جميع الملفات البرمجية والتوثيقية الناتجة أُنشئت داخل المجلد المخصص `database/`، وهي جاهزة للاستيراد المباشر واليدوي إلى أي مشروع Supabase سحابي أو محلي عبر SQL Editor أو Supabase CLI.

## 3. القرارات الهندسية والمعمارية (Key Architectural Decisions)

### 3.1 النمط الهجين بين الجداول المنظمة والبيانات المرنة (Normalized Core + JSONB)
- **الأعمدة المفهرسة:** تم تنميط الأعمدة الأساسية اللازمة للبحث والتصفية والفرز والربط كأعمدة مستقلة ومفهرسة (مثل `id`, `listing_number`, `price`, `currency`, `property_type`, `purpose`, `status`, `is_reserved`, `seeker_id`, `advertiser_id`).
- **حقول JSONB:** تم استخدام نوع `JSONB` للبيانات المعقدة والمتغيرة بطبيعتها (مثل تفاصيل الموقع الجغرافي `location`، خصائص العقار المعمارية `attributes`، بنود العقد `clauses`، سجل التواقيع الرقمية `electronic_signatures`، وتاريخ النسخ والمراسلات `messages`)، مما يضمن التوافق الفوري مع كود React/TypeScript الحالي دون الحاجة إلى تفكيك وإعادة صياغة استدعاءات الـ Frontend.

### 3.2 هندسة حماية الحصرية وقفل الحجز المؤقت (Exclusive Lock Engine)
لمنع حدوث حجوزات متزامنة للعقار نفسه (وهي مشكلة شائعة تؤدي للنزاعات الميدانية في اليمن):
1. **قيد الفهرس الجزئي الفريد (Partial Unique Index):**
   ```sql
   CREATE UNIQUE INDEX idx_single_active_booking_per_listing 
   ON public.property_bookings (listing_id) 
   WHERE (status = 'active');
   ```
   يضمن استحالة وجود أكثر من حجز واحد نشط لنفس العقار في آنٍ واحد على مستوى محرك قاعدة البيانات مباشرة.
2. **المشغل التلقائي `fn_sync_listing_booking_state`:**
   عند تحول الحجز إلى `active`، يقوم المشغل تلقائياً بتحديث العقار المرتبط ووضع `is_reserved = TRUE` وضبط `reserved_until`، مما يؤدي تلقائياً إلى إخفاء العقار عن الجمهور والزوار في سياسات RLS. وعند إلغاء الحجز أو انتهاء مدته، يُعاد العقار تلقائياً كعقار متاح ما لم يكن قد أُتم بيعه أو تأجيره.

### 3.3 حتمية إتمام الصفقة وحظر إعادة فتح العقار المكتمل (Irreversible Completed Deals)
- عند إتمام المعاملة واستيفاء متطلبات التوقيع وسند القبض ومحضر الاستلام، يُحدث المشغل `fn_complete_deal_and_close_listing` حالة العقار إلى `completed`، وتُسجل النتيجة (`sold` أو `rented`) مع رقم المحضر الدائم (`DOS-2026-XXXX`).
- يفرض المشغل `fn_prevent_reopening_completed_listing` منعاً باتاً على أي محاولة لتغيير حالة العقار المكتمل إلى حالة سابقة، مما يمنع التلاعب بملكيات الصفقات المنفذة ويحفظ الأرشيف السيادي للمنصة.

### 3.4 التكامل السلس مع Supabase Auth و RLS
- تم تزويد جدول `users` بالحقل `supabase_user_id UUID REFERENCES auth.users(id)` لربط مستخدمي التطبيق بحسابات المصادقة الرسمية في Supabase (سواء عبر البريد الإلكتروني أو الرسائل النصية SMS OTP).
- تم تفعيل سياسات Row Level Security على جميع الجداول، وتوفير دوال مساعدة `current_app_user_id()` و `current_app_user_role()` و `is_admin_or_moderator()` التي تتيح التحقق الفوري من صلاحيات الجلسة دون الاعتماد على مدخلات العميل غير الموثوقة.

## 4. سيناريوهات وحالات الحافة التي تمت معالجتها (Edge Cases Handled)

1. **النزاع أثناء سريان الحجز:** جدول `property_bookings` مزود بالحقول `is_disputed` و `dispute JSONB` مما يسمح بتجميد الإجراءات وإحالتها لمسؤول النزاعات (`reporter_admin`) دون كسر قفل الحجز أو إعادة عرض العقار بالخطأ.
2. **تعديل بنود العقد بعد الاعتماد:** أي تغيير في مسودة العقد يرفع رقم الإصدار `current_version` تلقائياً ويلغي اعتمادات الطرفين السابقة (`first_party_approval = false` و `second_party_approval = false`) لمنع التعديل الصامت على الشروط المتفق عليها.
3. **حماية خصوصية الموقع الجغرافي:** حقل `location->>'isApproximate'` يدعم التمويه الجغرافي الميداني لحماية خصوصية المعلنين وملاك العقارات من التطفل.
4. **المعاملات المالية المتعددة العملات:** دعم كامل ومفحوص للريال اليمني والدولار والريال السعودي مع قيود التحقق `CHECK (currency IN ('YER', 'USD', 'SAR'))` و `CHECK (price >= 0)`.

- **البيئة الحالية:** المشروع المحلي يعمل بكفاءة، وجميع واجهات النظام ونقاط النهاية الحالية مستمرة في العمل دون أي انقطاع.
- **التوصية التالية للمستخدم:** اتباع الدليل العملي في `database/IMPORT_DATABASE_AR.md` لفتح Supabase Dashboard، ولصق محتويات `schema.sql` ثم `seed.sql` للبدء الفوري في استخدام المنظومة.
