# 12. التحليل الأمني وحوكمة الصلاحيات وحماية البيانات (SECURITY & PERMISSIONS AUDIT)
## منصة «دلنّي» العقارية الوطنية الذكية (DALANI)

---

### 1. الإطار الأمني العام للمنظومة
تم تصميم منصة «دلنّي» على مبدأ **«الدفاع المتعمق» (Defense-in-Depth)**، بحيث لا تعتمد حماية المنصة على واجهات المستخدم فقط، بل تتكامل الحواجز الأمنية عبر طبقات التطبيق وقاعدة البيانات السحابية لمنع الاحتيال، التلاعب بالأسعار، أو ازدواج بيع العقارات في السوق اليمني.

---

### 2. مقارنة التحقق في الواجهة (Client) مقابل التحقق في السيرفر (Server/RLS)

| المجال الأمني | التحقق في الواجهة (Client-Side Guard) | التحقق في السيرفر وقاعدة البيانات (Server-Side / RLS) | التقييم الهندسي |
|:---|:---|:---|:---:|
| **حماية المسارات الإدارية** | مكون `ProtectedRoute` يفحص `currentUser.role` ويعيد التوجيه للرئيسية إذا كان الدور غير مصرح. | استعلامات Supabase تتطلب JWT Role مصرح به وتمنع الوصول للجداول الحساسة. | **آمن ومتكامل** |
| **صمام منع التعارض وقفل الحجز** | الواجهة تخفي زر الحجز إذا كان `isReserved === true`. | السيرفر ينفذ استعلام فحص إلزامي لمنع إدراج حجز نشط متزامن لنفس `listing_id`. | **آمن جداً (Double-Checked)** |
| **تعديل بنود العقد** | الواجهة تلغي الاعتمادات السابقة تلقائياً وتزيد رقم الإصدار (`version + 1`). | قاعدة البيانات تحتفظ بسجل الإصدارات `version_history` وترفض التوقيع على مسودة قديمة. | **محمي ضد التعديل الصامت** |
| **سرية هوية المُبلّغ** | الواجهة تخفي بيانات المُبلّغ تماماً عند استعراض البلاغات من حساب المعلن. | استعلامات جدول البلاغات تحجب أعمدة `reporter_phone` و `reporter_name` عن غير الإدارة. | **سري ومشفر** |
| **وثائق الملكية الخاصة (البصائر)** | تُعرض فقط للمعلن ولفريق التحقق `verifier` ومدير النظام. | تُخزن في حقل محمي `private_documents` ويُمنع إرجاعها في استعلامات البحث العامة. | **محمي بخصوصية صارمة** |

### 3. صمام قفل الحجز الحصري ومنع التعارض المزدوج (Anti-Conflict Lock)
* **المشكلة التي يعالجها:** منع سيناريو بيع أو حجز نفس العقار لشخصين في نفس التوقيت (Double-Selling / Race Condition).
* **آلية الصمام البرمجية:**
  1. عند طلب قبول الحجز (`acceptPropertyRequest`):
     ```typescript
     // فحص استباقي صارم لضمان عدم وجود حجز نشط آخر
     const existingActiveBooking = bookings.find(
       b => b.listingId === request.listingId && b.status === 'active'
     );
     if (existingActiveBooking) {
       throw new Error('تعذر إتمام الحجز: العقار مرتبط حالياً بحجز نشط قائم.');
     }
     ```
  2. يتم تحويل حالة العقار في جدول `listings` إلى:
     * `is_reserved: true`
     * `active_booking_id: newBooking.id`
     * `reserved_until: new Date(Date.now() + 48 * 3600000).toISOString()`
  3. يتم استبعاد العقار آلياً من كافة محركات البحث وحجبه عن أي طلبات حجز جديدة حتى انتهاء المدة أو الإلغاء الرسمي.

### 4. حماية سرية البصائر الشرعية ووثائق الملكية العقارية
* **حساسية البيانات في اليمن:** تُعد "البصيرة الشرعية" وثيقة شديدة الحساسية والخطورة في اليمن، وقد يؤدي تسريب صورتها أو تفاصيلها إلى ادعاءات ملكية باطلة أو مشاحنات قبلية وقانونية.
* **إجراءات الحماية المتخذة:**
  1. **الموقع التقريبي (Fuzzy Location):** إخفاء إحداثيات GPS الدقيقة وعرض دائرة نصف قطرها التقديري 500 متر على الخريطة العامة للزوار والمستخدمين العاديين.
  2. **حجب رقم الصك وسجل الأمين:** لا يظهر رقم البصيرة أو اسم الأمين الشرعي للعامة، بل تظهر شارة خضراء تفيد بأن *"صك الملكية تم فحصه ومطابقته لدى إدارة التحقق"*.
  3. **كشف العنوان الميداني المشروط:** لا يتم تسليم عنوان العقار الدقيق ورقم الشارع للمشتري/المستأجر إلا بعد قبول طلب الحجز وتأكيد موعد المعاينة الميدانية رسمياً.

### 5. صمام منع التعديل الصامت للعقود (Anti-Silent Modification Protection)
* **المشكلة:** قيام أحد الأطراف (مثلاً المؤجر) بتعديل بند في العقد (مثل زيادة مبلغ الإيجار أو تغيير شروط الصيانة) بعد أن يكون الطرف الآخر قد وافق عليه مسبقاً، دون علم الطرف الثاني.
* **آلية الصمام البرمجية المطبقة في `ContractDocumentModal` و `AppContext`:**
  1. كل تعديل على أي بند في مسودة العقد يستدعي تلقائياً زيادة رقم الإصدار: `currentVersion = currentVersion + 1`.
  2. يتم تدوين ملخص التعديل في `versionHistory` مع اسم وهوية الطرف الذي قام بالتعديل.
  3. **تصفير الاعتمادات فوراً:** يتم شطب أي موافقات سابقة للطرفين:
     * `firstPartyApproval = false`
     * `secondPartyApproval = false`
     * `firstPartyApprovedAt = undefined`
     * `secondPartyApprovedAt = undefined`
  4. تظهر رسالة تحذيرية صفراء للطرف الآخر: *"تنبيه: تم تعديل مسودة العقد، ويجب إعادة مراجعة البنود والموافقة على الإصدار الجديد رقم (X)"*.
  5. يُمنع التوقيع الإلكتروني على العقد نهائياً ما لم تكن موافقات الطرفين مطابقة تماماً لرقم الإصدار الحالي (`firstPartyApprovedVersion === currentVersion && secondPartyApprovedVersion === currentVersion`).

### 6. إدارة الجلسات والأمان ومكافحة الهجمات السيبرانية
1. **التحقق برمز الهاتف (SMS OTP):** ميزة مدعومة لمنع اختراق الحسابات العقارية من أجهزة جديدة.
2. **رصد محاولات التخمين (Brute-Force Monitor):** قفل الحساب مؤقتاً بعد 3 محاولات دخول فاشلة متتالية وتسجيل عنوان الـ IP في لوحة التهديدات.
3. **الطرد الفوري للجلسات المشبوهة (Kill Session):** قدرة مدير النظام على إنهاء جلسة أي موظف أو مستخدم لحظياً وحظر عنوان الـ IP بنقرة زر واحدة.
4. **سجل التدقيق غير القابل للتعديل:** حفظ كل حدث إداري مع الطابع الزمني والأثر لمنع التلاعب الوظيفي الداخلي.
