# 13. آلات الحالة المحدودة وتدفقات الكيانات (ENTITY STATUS FLOWS & STATE MACHINES)
## منصة «دلنّي» العقارية الوطنية الذكية (DALANI)

---

### 1. آلة حالة العقار والإعلان (`ListingStatus`)

يتحكم الكيان الرئيسي `Listing` في دورة المعروض العقاري عبر 11 حالة دقيقة محددة في `src/types/index.ts` (السطور 32-44):

| كود الحالة (`ListingStatus`) | المسمى بالعربية | المعنى والظهور للجمهور | الشروط والمحددات للانتقال للحالة التالية |
|:---|:---|:---|:---|
| `draft` | مسودة أولية | يراها المعلن فقط في لوحة إعلاناته. | اكتمال الحقول الإلزامية في معالج النشر ➔ الانتقال لـ `under_review`. |
| `pending_completion` | بانتظار الاستكمال | مسودة ناقصة لبعض البيانات الأساسية. | استكمال الصور أو الموقع ➔ الانتقال لـ `under_review`. |
| `under_review` | قيد المراجعة | محجوبة عن الجمهور، معروضة في طابور مراجعة الإدارة (`ModerationPage`). | فحص الكادر الإداري ➔ قبول (`published`)، طلب تعديل (`needs_changes`)، أو رفض (`rejected`). |
| `pending_verification` | بانتظار التحقق | فحص خاص لبصيرة الملكية أو ترخيص المنشأة. | اعتماد المستندات ➔ منح شارة التوثيق والنشر كـ `published`. |
| `needs_changes` | مطلوب تعديله | يراها المعلن مع ملاحظات النواقص المحددة من الإدارة. | قيام المعلن بإجراء التعديلات المطلوبة ➔ إعادة الإرسال لـ `under_review`. |
| `published` | منشور ونشط | ظاهر لجميع الزوار والمستخدمين على الخريطة وقوائم البحث. | متاح للحجز؛ عند قبول حجز يتحول داخلياً لـ `isReserved: true` دون تغيير حالة النشر حتى إتمام الصفقة. |
| `suspended` | موقوف مؤقتاً | محجوب عن الجمهور نتيجة بلاغ نزاع أو رغبة مؤقتة للمعلن. | التحقيق الإداري ➔ فك الإيقاف (`published`) أو الرفض والإلغاء (`rejected`/`cancelled`). |
| `expired` | منتهي الصلاحية | تجاوز الإعلان مدة الباقة المحددة (مثلاً 60 يوماً). | قيام المعلن بتجديد الباقة ➔ العودة لـ `published`. |
| `rejected` | مرفوض نهائياً | إعلان مخالف للشروط، احتيالي، أو غير لائق. | حالة نهائية وأرشفة في سجلات النظام. |
| `cancelled` | ملغى | تم إلغاؤه بطلب صريح من المعلن قبل التعاقد. | حالة نهائية غير نشطة. |
| `completed` | مكتمل ومباع / مؤجر | تم إتمام الصفقة وتوقيع العقد والمخالصة المالية (`dealOutcome: sold/rented`). | حالة نهائية تظل في الأرشيف الرسمي كمرجع وسند إثبات مع حجبها عن البيع مجدداً. |

### 2. آلة حالة الحجز العقاري الحصري (`PropertyBookingStatus`)

تحدد مسار الحجز المؤقت في جدول `property_bookings` (`src/types/index.ts` السطر 313):

```
       [طلب حجز مقبول]
              │
              ▼
          ┌────────┐
          │ active │ ◄── حجز حصري نشط (مؤقت لـ 48 ساعة مع قفل العقار)
          └───┬────┘
              │
      ┌───────┼────────────────┐
      │       │                │
      ▼       ▼                ▼
┌───────────┐ ┌───────────┐ ┌───────────┐
│ completed │ │ cancelled │ │  expired  │
└───────────┘ └───────────┘ └───────────┘
 (إتمام الصفقة (إلغاء برغبة (انتهاء المهلة
  وتوقيع العقد) أحد الطرفين) التنازلية 48h)
```

1. **`active` (نشط وحصري):**
   * يبدأ فور قبول المعلن للطلب؛ يتم تشغيل العداد التنازلي لمدة 48 ساعة وقفل العقار في قاعدة البيانات.
2. **`completed` (مكتمل الصفقة):**
   * انتقال ناجح بعد استيفاء الشروط الثلاثة: توقيع العقد، سند القبض المالي، ومحضر التسليم.
3. **`cancelled` (ملغى):**
   * إلغاء اختياري من أحد الطرفين مع تدوين التصنيف (تراجع المشتري، عدم الرضا بالمعاينة، خلاف على السعر...).
4. **`expired` (منتهي المدة):**
   * انتهاء مهلة الـ 48 ساعة دون إتمام العقد أو تمديد المهلة، مما يحرر صمام العقار ويعيده للجمهور تلقائياً.

### 3. آلة حالة العقد العقاري الموحد (`ContractStatus`)

تحدد دورة حياة المستند القانوني في `property_contracts` (`src/types/index.ts` السطر 498):

```
    [توليد العقد من الحجز]
               │
               ▼
           ┌───────┐
           │ draft │ ◄── مسودة العقد (تعديل البنود + إصدارات V1, V2...)
           └───┬───┘
               │
               ▼
       ┌──────────────┐
       │ under_review │ ◄── قيد التدقيق والمراجعة القانونية
       └───┬──────────┘
           │
           ▼
    ┌──────────────────┐
    │ pending_approval │ ◄── بانتظار موافقة الطرفين
    └───┬──────────────┘
        │ (موافقة الطرف الأول + الثاني أو فك قيد الإدارة)
        ▼
       ┌──────────┐
       │ approved │ ◄── معتمد بالتراضي بانتظار التوقيع
       └───┬──────┘
           │ (التوقيع الإلكتروني بالبصمة الرقمية ورقم الهوية)
           ▼
        ┌────────┐
        │ signed │ ◄── عقد نافذ وموثق رسمياً (جاهز للطباعة والحفظ PDF)
        └────────┘
```

### 4. آلة حالة طلب العقار (`PropertyRequestStatus`)

تحدد مسار الطلب الأولي قبل تحويله لحجز رسمي (`src/types/index.ts` السطر 276):

1. **`pending` (معلق):**
   * يبدأ فور إرسال الباحث (أحمد العولقي) لطلب الحجز أو المعاينة، بانتظار رد المعلن.
2. **`accepted` (مقبول):**
   * المعلن وافق على الطلب؛ ينتج عنه آلياً إنشاء سجل حجز نشط في `property_bookings` وقفل العقار.
3. **`rejected` (مرفوض):**
   * رفض المعلن للطلب مع تدوين السبب.
4. **`cancelled` (ملغى من الباحث):**
   * قيام الباحث بسحب طلبه قبل أن يوافق عليه المعلن.

### 5. حالات حسابات المستخدمين والمنشآت
* **حالة المستخدم (`activeStatus: boolean`):**
  * `true`: حساب نشط ومخول.
  * `false`: حساب معطل ومجمد (لا يستطيع نشر إعلانات أو تقديم حجوزات).
* **توثيق هاتف المستخدم (`phoneVerified: boolean`):**
  * شرط إلزامي لنشر العقارات أو الدخول في صفقات التعاقد.
* **توثيق المنشأة العقارية (`isVerified: boolean`):**
  * يتطلب مطابقة السجل التجاري الحكومي لمنح الصلاحيات المتقدمة للمكاتب والشركات.
